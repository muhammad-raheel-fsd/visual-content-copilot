## Q1

**Question:** Explain the four core database modelling concepts: Entity, Attribute, Relationship, and Identifier. Use the Student example from the book to illustrate each.

**Answer_hint:**
Cover all four, with the Student example throughout:

1. **Entity (verbatim):**
   "An entity is a real-world object, person, place, event, or concept about which data is stored in a database."
   Example: Student, Teacher, Course, Book, Employee.
   The Student entity is any student the school keeps data about.

2. **Attribute (verbatim):**
   "An attribute is a property or characteristic of an entity. It describes specific information about an entity."
   For the entity Student, the book lists these attributes: Student Name, Roll Number, Class, Age.
   Each attribute captures one fact about a student.

3. **Relationship (verbatim):**
   "A relationship shows how two or more entities are connected with each other."
   Example: A Student enrols in a Course. Here, "enrols in" is the relationship between Student and Course.
   The relationship lets us link two entities so the database can answer questions like "which students are in this course?"

4. **Identifier (verbatim):**
   "An identifier is an attribute that uniquely identifies each record or object of an entity."
   For Student, the book says Roll Number can be used as an identifier because each student has a unique roll number.
   The identifier makes sure no two records are ever confused.

Close with: Together these four concepts (Entity, Attribute, Relationship, Identifier) form the backbone of database modelling. Design starts by listing entities, attaching attributes, naming relationships, then picking an identifier.

## Q2

**Question:** Explain the five "Key database concepts" from the Understanding Databases section: Relational Database, Table, Column, Primary Key, Foreign Key. Draw and explain Figure 4.3 (Student + Department tables) to show how a foreign key links two tables.

**Answer_hint:**
Cover all five verbatim definitions and the figure:

1. **Relational Database:** A database that stores data in tables (rows and columns) and links them using relationships.
2. **Table:** A collection of related data organised in rows (records) and columns (fields).
3. **Column:** A property or characteristic of an entity (e.g., name, age).
4. **Primary Key:** A unique identifier for each record in a table.
5. **Foreign Key:** A field that links one table to another by referring to the primary key of another table.

**Draw Figure 4.3:**

```
Table: Student                       Table: Department
+--------+---------+-----+--------+   +--------+------------------+
| RollNo | Name    | Age | DeptID |   | DeptID | DeptName         |
+--------+---------+-----+--------+   +--------+------------------+
| 101    | Kiran   | 20  | 1      |   | 1      | Computer Science |
| 102    | Ibrahim | 21  | 2      |   | 2      | Electronics      |
| 103    | M Kamal | 20  | 1      |   | 3      | Mechanical       |
| 104    | Zainab  | 22  | 3      |   +--------+------------------+
+--------+---------+-----+--------+
     ^                        ^
     |                        +----- Foreign Key
     +----- Primary Key              (links to Department.DeptID)
```

Explain the figure:
- **RollNo** is the primary key of Student. Each row has a unique RollNo (101, 102, 103, 104), so we can always find exactly one student.
- **DeptID** is the primary key of Department. Each department has a unique ID (1, 2, 3).
- **DeptID in Student** is a foreign key. Its value refers to the DeptID primary key in Department. So Kiran (RollNo 101) has DeptID 1, which links to Department row 1 (Computer Science).
- Each row of the table is called a **record** (also called a tuple). Each cell is a **field** holding one attribute value.
- The link between the two tables lets us answer questions like "which department is Kiran in?" by following DeptID from Student to Department.
